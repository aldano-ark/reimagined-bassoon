# Shared contracts

Store language-neutral API schemas, shared fixtures, and behavioral examples here when a product requires them. There is no runtime library or invented API in the empty template.

Each contract states its owner, consumers, versioning rules, and compatibility expectations. Platform implementations can use native models internally. Keep generated client code within its consuming platform and document generation when it is introduced.

Product acceptance criteria belong in `docs/specs/`; architecture rationale belongs in `docs/decisions/`.
